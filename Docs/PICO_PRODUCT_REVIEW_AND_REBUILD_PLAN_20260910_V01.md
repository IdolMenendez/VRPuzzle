# PersonallyPuzzledVR：面向 PICO 上架的产品审视与重做方案

日期：2026-09-10。审视对象：当前 V82、五个可玩模型、53 个拼装部件。本文是产品提案，未实施玩法重构、接入支付或提交商店。发行地区尚未确认，暂按中国大陆优先、海外单独准备的方式列出分支。

## 1. 判断与定位

现有版本已经证明“在 VR 中抓取并拼装模型”的技术链路能跑通，但尚未证明新玩家能独立理解、持续享受，并愿意为整套内容付费。当前最重要的工作是建立可理解、有变化、有回报的产品循环。

建议定位：**一间可以坐着玩的微缩工坊，把散件拼成会动、有故事、可以长期收藏的小世界。** 主体为单人、轻度空间解谜、舒适拼装；尽量让基础关卡在平台授权及当地合规允许的条件下离线使用。单次约 10–20 分钟是设计目标，不能把它当作已经测出的时长。

保留暖木工坊、语义部件、抓取—移动—释放吸附、音效反馈、稳定的 XR 原点和现有回归工具。重新设计初次体验、选关信息、关卡差异、收藏和进度系统。工程上逐步替换，不为“重做”再写一遍已验证的设备底层。

## 2. 已发现的问题与优先级

P0：影响完整体验或发行；P1：影响付费价值；P2：稳定后扩展。

| 方面 | 当前证据 | 玩家或项目影响 | 推荐处理 |
| --- | --- | --- | --- |
| 收藏闭环，P0 | 收藏场景存在；完成页有效物理按钮调用 EnterSelection；旧收藏入口组件禁用。API 自动测试可以进入，不等于玩家可进入 | 拼装成果没有稳定可达的归宿 | 工坊固定“收藏”入口，完成后提供收藏、下一关、继续把玩 |
| 中途进度，P0 | 存档结构只含星级、最高解锁关及设置，关卡启动重置零件；没有部件进度字段 | 关闭进程后无法恢复拼到一半的状态 | 保存已装部件 ID、关卡版本、当前关；逐次吸附和暂停时保存，冷启动“继续拼装” |
| 解锁规则，P0 | 当前 Bootstrap 的 unlockAllLevelsV57=1，会在读档时解锁五关 | 测试便利配置替代正式设计，无法判断真实新手路径 | 明确教学门槛与自由选关；测试开关移入开发配置。自由选关本身可以是正式设计 |
| 输入与引导，P0 | 选关首次捏合居中锁定、再次独立捏合进入；当前零件启用外部原生手势输入 | 防误触逻辑可靠性与操作可发现性是两个问题；现有测试不能证明普通玩家看得懂 | 保留居中预览，增加明确“开始/继续”动作和提示；实际支持的每种输入都必须独立完成全流程 |
| 模型一致性，P0 | 旧 16 部件铁塔仍有完成/收藏活跃引用；可玩铁塔为另一套 10 部件模型，另有预览模型 | 玩家拼好的模型与展示模型存在不一致风险；重复资源也占空间 | 一个语义装配定义生成选关、拼装、完成、收藏；允许 LOD，外观和部件身份必须一致 |
| 成绩与气质，P1 | 1–5 星由耗时和提示次数决定；五关星级基准分别为 150/300/480/420/390 秒 | 放松、观察、使用辅助反而降低成绩；基准不是实测游玩时长 | 默认舒适模式取消计时与提示惩罚；计时挑战独立为可选模式 |
| 装配挑战，P1 | 已有依赖关系与进场方向等能力；铁塔实际场景吸附距离约 14.5–18 cm、角度 135–180° | 较大容差可能掩盖操作问题，也削弱空间推理；不能仅据数值判定手感坏 | 真机测抓取尺度和识别性，依部件配置容差；舒适辅助与挑战规则分别调节 |
| 美术和可读性，P1 | 新截图中深色零件与背景接近、零件密集；选择模型放大，信息主要靠场景装饰；独立 Garden 更明亮，但不在当前 APK 关卡中 | 装配关系不清楚、功能入口不突出；品牌气质未统一 | 工坊保留暖色，零件用清晰材质与色块；改善任务照明、托盘分组和轮廓，先做一个关卡美术基准 |
| 内容完整性，P1 | 小屋13、船13、铁塔10、宝塔9、风车8；飞机仅“模型预览 未开放” | 五个题材尚不等于五套有差异的玩法；未开放展品抢占展示位置 | 优先深度打磨现有内容；飞机完成可玩标准后才进入主关卡列表 |
| 设备性能，P0 | 船约205万三角面；活跃旧铁塔约257万三角面。V82 mesh compression 保持三角索引/数量 | 包体 230.6 MB 并不证明真机帧率、热稳定、内存合格；源模型面数不是同屏实测面数 | 先测实际可见集和 GPU/CPU，再做重拓扑、LOD、材质批次、灯光与透明物优化 |
| 商店版本，P0 | 最新 APK 仍为 Android Debug 签名、versionCode 1；未找到业务代码中的商业服务调用 | 测试包不能等同可运营发行版本；搜索结果不代表 SDK 包完全不存在 | 确认发行主体、正式签名、应用身份、版本迁移、平台授权及区域流程 |

## 3. 完整玩家流程

正常回访路径：**进入工坊 → 继续拼装/选关 → 拼装 → 模型启动 → 收入收藏 → 下一件。** 设置和退出始终有清晰入口。

首次体验先校准桌高和惯用手，用一个 4–6 块的小模型教会抓取、旋转、释放、提示。教程直接用玩家动作推进；没有看完长说明才能操作的前置要求。目标为一分钟内第一次成功吸附，2–3 分钟理解基本循环，均需新手实测验证。

建议第一件是小风车：装底座和塔体，再装轴与叶轮，最后轻拨一下，叶轮转动、窗户点亮。玩家随即把它放入收藏架，看到后续几件作品的轮廓。第一次完成奖励必须在作品上发生，不能只换成“完成”文字。

第一次回访优先显示上次模型和“已装 6/13，继续”；重开单独入口并确认。摘戴、系统菜单、追踪丢失先暂停交互；恢复追踪后给玩家准备时间。进程仍存活时的恢复与进程已被回收后的读档分别测试。

## 4. 选关与收藏

保留有辨识度的机械展柜，但把功能说明放在展品附近：名称、已装/总部件、难度、预计时长、已完成标记、拥有状态，以及清楚的开始/继续按钮。预计时长来自测试，初期可以不显示。居中展示不自动触发购买或入关。

关卡入口的产品状态：未教学解锁、可开始、进行中、已完成、未购买、内容不可用。付费权限、教学解锁、装配进度分开判断；不能因为存档写了一个星星就获得 DLC，也不能因购买恢复而清空进度。

三个主题章节可作为首发内容框架：生活小景、旅行地标、机械奇想。完成教学后允许在已拥有内容内自由挑选，用“建议下一件”代替全部强制线性锁关。换页和旋转展柜可坐着完成，避免要求大幅转身或走动。

收藏架展示玩家真正拼出的同一套部件装配；可拿近观察、旋转、触发机关、拍照。完成数量逐步布置工坊，装饰奖励直接发放，不增加无必要的货币系统。收藏空间先做少量展位和分页，不能一次常驻所有高模。

## 5. 拼装为什么值得玩

三种体验层次共同构成差异：看轮廓和接口辨认部件；理解底座—支撑—外壳等合理装配关系；启动简单机关验证成果。已有依赖系统值得复用，但不要把每一块都锁成唯一顺序。

| 题材 | 主要装配体验 | 完成后的互动 |
| --- | --- | --- |
| 花园小屋 | 墙体、屋顶、花园分区；少量合理自由顺序 | 开门亮灯、烟囱冒烟，呈现生活场景 |
| 帆船 | 船体层级、甲板和桅杆关系；不用模拟复杂绳结 | 拉动绞盘或升帆，出现水面与船声 |
| 铁塔 | 对称支撑与向上收束，避免纯重复搬运 | 触发灯光、观察结构；细杆保持可抓取尺度 |
| 宝塔 | 楼层和屋檐节奏，体现形状差异 | 风铃与局部灯光反馈 |
| 风车 | 轴、叶轮、传动关系 | 亲手拨动叶轮，让机关带动起来 |

每关先选一项能实现且可感知的机关，不把所有建议都堆入首发。机关是对装配的回报，不是拼完后突然出现另一套操作教学。

提示采用自愿逐级帮助：指出可装的一组部件 → 显示接口/方向 → 显示精确位置。舒适模式使用提示不扣奖励；不能通过付费解决设计导致的卡关。大容差需要与真实部件尺度、对称性、手势精度共同校准，不统一强行缩到几厘米。

放错时优先清楚说明为何未连接，并平稳回到可达托盘；提供整理零件、回收落物和可撤销的最后一步。单手可以完成全部必需动作，双手用于方便的观察和缩放。常用物体处于舒适近手范围，不要求长时间举臂或俯身捡拾。

## 6. 首发范围与美术生产

建议先做 1 个达到发行品质的完整关卡，再做 3 个体现不同装配体验的关卡。只有这三个关卡的新手反馈通过，才扩充到约 8 个精修模型和 1 个短教程。8 个是生产目标，不是商店最低要求，也不意味着自动具备某个小时数。实际内容时长、重复游玩意愿和制作成本决定最终数量与售价。

确立“温暖工坊 + 色彩清楚的微缩作品”基准。Garden 可以作为更亲切材质和轮廓的参考，但需要完整接入同一部件系统，不能直接把独立展示稿宣传成已在 APK 中可玩。统一项目名、游戏内 MODEL BUILDER 名称、图标及商店文案；正式命名前核查名称和品牌使用权。

资产产线：概念图 → 语义装配设计 → 单个部件可读性/完整性检查 → 生产网格和 UV → 材质、碰撞体和抓取点 → 装配关系 → 三种距离 LOD → 真机检验 → 展示复用。生成模型只是来源，不能免除拓扑、薄片、内面、材质及商业使用授权检查。保留项目既定语义拆件标准和接受记录。

几何优化优先解决高面数船、重复铁塔和展柜同屏资源；近距离拿在手上的部件优先保留轮廓，远景细节通过 LOD/贴图处理。压缩、减面、运行内存和 GPU 花销分别测量，不再只用 APK 大小评判优化。

## 7. 商业化

推荐首发采用**买断完整基础内容**，后续经需求验证再出售有明确内容的主题关卡包。完整基础内容不拆成多个强制付费门槛；不做广告、体力、抽奖或收费提示。DLC 应贡献新的题材和装配互动，不只是换颜色。

定价先做假设测试：例如大陆 ¥49–69、海外 $9.99–14.99 作为访谈选项；这些不是当前竞品统计、平台价格档位或保证可售的建议定价。让体验过三个代表关卡的人评价实际价值，再结合最终内容量、地区、价格档位和净收入确定价格。当前五关不能直接据数量定价。

可准备一个完整小模型作为试玩内容，投放方式先核对当前商店/测试渠道支持。不要依据旧 PICO Lab 博客默认该渠道今天可付费，也不要让试玩入口被误认为基础购买后仍需另购。

PICO 官方公开支持个人开发者自助发布和付费发行；具体身份、地区、结算和分发渠道仍需在目标账号确认。[官方公告](https://developer.picoxr.com/blog/self-publishing-and-paid-distribution/)

PICO 平台提供版权校验、应用内购、成就等能力；有能力不代表当前项目已经接入，也不代表首发需要全部接入。[PICO 开放平台](https://developer-cn.picoxr.com/pps/)

实现顺序：先做基础应用的正式身份、授权和发行配置，再按是否实际售卖 DLC 决定内购。若做 DLC，权益恢复、取消、失败、网络中断、账号切换、退款后权益与已存进度的处理都要定义；采用平台支持的订单校验，回调和重试幂等。永久商品不按消耗品反复消费。密钥不放客户端。支付结果以平台可信记录为准，游戏进度独立保留。

商业判断看试玩到购买意愿、实际完成率、卡关与退款原因、每个模型的制作成本，以及收入能否覆盖下一批内容。回本测算使用“售价扣实际平台费用、税费、退款后的每份净收入”，不预设未经确认的固定分成或销量。

## 8. PICO 发行路径与验收

先确定大陆还是海外以及支持的具体机型、系统与输入设备。当前代码有大量 Swan 特定逻辑，不能假设已经普适覆盖零售 PICO 4/4 Ultra 等设备；逐一验证目标设备，按验证结果申报支持范围。保持现有 OpenXR 沉浸式项目可行路线，是否采用新空间框架另作目标硬件评估。

大陆路径需先确认开发者主体、应用类别、收费结算以及游戏许可/备案要求。PICO 国内协议 5.6 要求适用的许可/备案材料，5.7 明确中国地区游戏应用依法接入实名、防沉迷及适龄提示等。具体到本作的版号/出版、主体及接入材料应向平台确认；不能把“个人可付费发行”解读为这些要求被免除。[PICO 国内开发者服务协议](https://developer-cn.picoxr.com/terms/)

海外路径单独核实地区分发、收款、内容评级、隐私和消费者规则，不直接套用国内材料。首发语言与客服能力应匹配地区；当前字体为固定字符子集，新增本地化文本需扩充字体及验证，不应假设支持任意语言。

提交前形成逐项证据：正式包名/应用 ID 与主体匹配；受控生产签名和可恢复保管；递增版本号；目标 SDK、权限及设备支持按当前审核项核对；隐私政策和第三方资源授权；实机录制的玩法视频、截图、图标、语言说明、支持邮箱与已验证功能描述。工程中的 com.bytedance 命名是否有权用于发行，需要由实际发行主体确认。

官方 PXRC 审核入口可访问，但本次抓取仅得到导航/错误页，未完整获取条款正文，因此本文没有声称已完成平台审核，也不将 72 FPS 等数值标成官方统一门槛。正式提交前在后台逐项核验。[PXRC 官方入口](https://developer.picoxr.com/document/distribute/functional-requirement-checklist-for-official-apps/)

建议内部发行门槛（需按机型实测，非平台硬性标准）：

- 至少 10 名未看过开发过程的玩家参加首轮测试，8 名以上能不靠旁人解释完成教程；记录首次抓取、首次吸附、选关迷失和提示使用情况。小样本用来暴露问题，不能据此预测全市场转化率。
- 支持的每种输入独立完成选关、拼装、收藏、设置、退出。手柄作为支持手柄机型的可靠完整路径，手势在相应机型达到同等闭环标准。
- 坐姿、惯用手、桌高、单手、系统重定位、追踪丢失和设备暂停均不破坏进度或产生危险位移。
- 所有目标机型完成不少于 30 分钟连续运行；报告 CPU/GPU 帧时间、内存峰值、发热后的表现。若选择 72 Hz，预算约 13.9 ms/帧；90 Hz 约 11.1 ms/帧，另留余量。真实刷新支持和审核要求必须另核实。可使用官方 Metrics HUD 观察指标。[工具说明](https://developer.picoxr.com/document/unreal/metrics-hud/)
- 进程被系统回收、冷启动、升级版本、保存失败等场景可恢复进度；正式付费路径按平台提供的测试方式验证购买/授权与权益恢复。
- 所有宣传中的模型实际可玩，核心循环没有断路，已知阻断问题为零，再提交审核。

## 9. 执行顺序与停止条件

| 阶段 | 做什么 | 进入下一阶段的条件 |
| --- | --- | --- |
| A 产品锁定 | 明确地区/硬件、资质路径、名称和目标用户；画出工坊与选关流程；选择首个完整模型 | 发行路径没有未解决的根本障碍；一个核心循环可清晰说明 |
| B 完整样板 | 短教程、一关、机关反馈、收藏、逐件存档和恢复、两类输入按硬件支持 | 新手独立完成；真机稳定；玩家能够说出有趣的具体瞬间 |
| C 三关验证 | 三种装配体验，验证重复游玩意愿；确定统一美术/性能产线 | 不同关卡被感知为不同体验；单关制作成本与商业规模匹配 |
| D 首发内容 | 扩展精修关卡、章节选关、工坊收藏、本地化、平台授权 | 内容真实完整；每关质量和机型表现达标 |
| E 商店候选版 | 正式签名、升级/恢复回归、区域接入、宣传素材、测试发行 | 按目标后台审核项检查完毕；没有阻断功能和严重舒适性问题 |
| F 正式运营 | 处理反馈、崩溃/退款问题、修补和更新；再决定 DLC | 基础体验稳定且有新增内容需求，才投入主题包 |
